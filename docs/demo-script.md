# Three-minute demo script

## Purpose

Show one supplier item moving through three connected Biscuit apps:

Supplier Inbox → Match Arena → Launch Board.

This is a prepared presentation script for the implemented workflow,
not a test-results document.

## Preparation

- Open all three apps in the private Biscuit workspace.
- Choose an existing single-pack shop product.
- Prepare a fictional supplier offer with an incorrect pack-size entry
  of 2 that can legitimately be corrected to 1 after clarification.
- Make the item easy to identify across apps.
- Rehearse the complete sequence before recording.

A genuine two-pack must remain distinct from a single unit.
Do not change a real product difference merely to complete a match.

## Timeline

| Time | Step | On screen | Suggested narration |
| --- | --- | --- | --- |
| 0:00–0:15 | Introduction | The three apps | “SKUpermatch connects Purchasing, Product Data and E-commerce at Respawn Retail, a fictional gaming-accessory retailer.” |
| 0:15–0:35 | 1. Create | Supplier Inbox: create the supplier item | “Purchasing enters a new offer. Its pack size is recorded as two.” |
| 0:35–0:50 | 2. Show the connection | Match Arena: find the same item | “Product Data sees the same shared record, not a separate spreadsheet copy.” |
| 0:50–1:10 | 3. Request clarification | Review the candidate single-pack product and ask a question | “The pack sizes differ. A similar name is not enough to confirm the match.” |
| 1:10–1:20 | 4. Receive the question | Supplier Inbox: show the question | “The question returns to Purchasing with the item context.” |
| 1:20–1:40 | 5. Clarify | Answer and correct the mistaken pack-size entry | “Purchasing clarifies that the offer is a single unit. The original entry was incorrect.” |
| 1:40–2:05 | 6. Confirm | Match Arena: review the answer, resolve the question and confirm the correct match | “Product Data selects or confirms the candidate shop product in Match Arena.” |
| 2:05–2:25 | 7. Review readiness | Launch Board: show the item and current blockers | “E-commerce sees the result. Blockers are calculated from current data and rules on each query.” |
| 2:25–2:50 | 8. Approve internally | Complete required information and selling price; approve when eligible | “Approval requires a confirmed product relationship, complete attributes, a selling price and no open question.” |
| 2:50–3:00 | Closing | Internally approved product | “Three team-specific tools, one shared process—from supplier uncertainty to internal approval.” |

Total planned duration: three minutes.

## Demonstration boundaries

- Show the same identifiable record throughout.
- Do not substitute disconnected records or fake a status transition.
- Describe synchronization as observed behaviour, not guaranteed latency.
- Internal approval is not a real shop upload.
- Not yet tested with separate user accounts.
- Do not present the demo as proof of separate-user authorization.
- Avoid displaying private emails, tokens, invitations or account settings.
- If using a fallback recording, identify it as a recording rather than
  presenting it as live execution.

## Recording

Record the eight-step workflow end to end.

The submitted video should be accessible without login and should show
the working apps, not only slides.

The three-minute video is separate from the live judging presentation.
